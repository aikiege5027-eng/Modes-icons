# 电梯相关图标汇总

**在线查看：https://aikiege5027-eng.github.io/Modes-icons/**

一张跨平台对照表，把同一个电梯模式在各个平台上用的图标横向摊开来看，并给出建议的「标准版」图标。

整个页面就是单个 `index.html`，没有构建步骤 —— 数据、样式、逻辑、以及每一处选型理由的注释全部在这一个文件里。用浏览器直接打开就能看。

## 页面内容

打开页面（首页）就是「最终整理版本」。页面最底部有一行「历史整理汇总」链接（地址 `#history`），点进去是原来的前三个页签，地址可以直接写到某一个页签：`#history/modes`、`#history/function`、`#history/live`。在历史页里点左上角的标题，或者按浏览器后退键，都能回到首页。

| 页签 | 条数 | 内容 |
|---|---|---|
| 模式图标 | 84 | 电梯运行模式（消防、检修、驻停、VIP…） |
| 梯形 / 功能图标 | 34 | 直梯 / 扶梯 / 人行道等梯型，以及功能类图标 |
| 其他实时数据图标 | 42 | 温度、振动、噪音、能耗、客流这类实时数据项 |
| 最终整理版本 | 114 | 前三个页签「标准版」图标按三大类汇总，图标库式网格：电梯模式 62 / 电梯类型、状态 23 / 实时数据 29 |

「最终整理版本」（首页，不显示页签条）是左右两栏：左边是分类导航（电梯模式 / 电梯类型、状态 / 实时数据），右边三类上下排成一长页，滚动时直接跨类别，导航跟着高亮当前滚到的那一类，点导航滚到那一类。搜索时导航上的数字变成各类的命中数，没有命中的类收起、导航项变灰。滚动联动在真实浏览器里的核对脚本是 `tools/out/final-scroll-spy/check-scroll-spy.mjs`（jsdom 量不了滚动位置）。不单独维护清单，每一类直接取对应页签的标准版那一列，表里换了图这里自动跟着变。页签计数 114 是三类方框之和，全页一共 98 个不同的图标。

- **电梯模式**：图标完全一样的几行合成一个方框（11 组，例如 fire 的 6 行合成「消防模式」），按每组第一行在模式图标表里的位置排；例外是 优先高区/低区、优先内呼/外呼、设置/未设置 三对按要求排在一起（`FINAL_MODE_ORDER_GROUPS`，每对挪到靠前那一格的位置）。合并的方框英文语义取第一行的、后面跟一个 ›，具体用在哪几个场景写在 tooltip 里；搜组内任一行的名字都能找到它。下面两行：中文语义（多个叫法时优先 IoT / 云视界、取第一个含汉字的）、英文语义（KFPS 优先，IoT Device Shadow 兜底；固定一行，放不下就省略号）；icon 库原始名称不在目录页显示，在 tooltip 和详情页里；梯型（直梯 / 扶梯）不在方框上标，写在 tooltip 和详情页的名称清单里。没选中的叫法写在 tooltip 的「其他叫法」里。
  点电梯模式的方框进入**图标详情页**：左边是透明底（棋盘格）的大预览，可切 16 ~ 512px（都是 16 的整数倍，16px 即原始尺寸），底部可翻上一个 / 下一个（← →）；右边是「下载」按钮（点开选 SVG / PNG）、各类名称，「常见名称」卡片 —— 列出模式图标表「英文」列里这个图标对应的全部名字（KFPS 与 IoT 两列，例如消防模式的 7 个），以及「场景释义」卡片 —— 模式图标表注释列的精简摘要（`FINAL_MODE_NOTES`，原文改了要人工同步，见那里的注释）。详情页有自己的地址 `#icon/<图标身份>`，浏览器后退键能退出，链接可以直接分享到某一个图标。
- **电梯类型、状态 / 实时数据**：按图标去重、字母序（例外：实时数据的运行方向固定按 上行 / 下行 / 左行 / 右行 排在扶梯/步道梯组最前；电梯类型、状态的扶梯组「扶梯 1」排在「扶梯」前面；电梯类型、状态各组都是线性图标在前、面形（名字带 filled / filded）在后，两段内各自按字母序；直梯组的线性段 10 格、面形段 8 格都按指定顺序排）。这两类的方框也能点进详情页（名称清单 / 常用于表达 / 场景释义，翻页只在本类里翻，顺序同网格）。电梯类型、状态的「常用于表达」先列梯形表里它自己的中文名，再列另外两类里用到同一张图的方框（例如梯门已开 → 保持开门（电梯模式）/ 梯门状态-已开门（实时数据））；场景释义来自 `FINAL_LIFT_NOTES`，梯形表没有注释列，是按中文名和图形另写的，需要设计确认。方框下两行：中文名 / 图标名。中文名在电梯类型、状态 取梯形表的「中文」列，在实时数据取「实时数据名称-实时数据细分」（表里细分留空或细分是「有数值」的只写名称，例如「能耗-有数值」写作「能耗」；一张图挂多行的写第一行、后面跟 ›，其余写在 tooltip 里）。实时数据分 通用 3 / 直梯 15 / 扶梯 11 三组（扶梯组的标题写作「扶梯/步道梯」；其中运行方向 左行 / 右行是步道梯的方向，详情页梯型标「步道梯」，见 `FINAL_LIVE_ROW_LIFT`）：「通用」里是不分梯型的三格 ——「无数据」（bias，合并了直梯、扶梯所有无数据 / 无数值的行）和「振动」（vibration-Horizonta，合并了轿门传感器振动 横向 / 纵向 / 垂直与齿轮箱振动，「其他实时数据图标」页签照旧列着原来的候选）和「温度」（thermometer，合并了轿门传感器温度与左 / 右扶手温度，扶手带那两张补画图不再收进来），具体是哪几项写在详情页里，通用组的详情页不列梯型；同一张图两个梯型都用的（dashboard-1），直梯、扶梯两组各放一个、各写各的名字，详情页里注明另一组也有。电梯类型、状态 再按梯型分三个小组：直梯 18 / 扶梯 4 / 步道梯 1（左侧导航不再往下分）。梯形表里有 11 个按要求不收进最终整理版本（`FINAL_LIFT_EXCLUDE`），「梯形 / 功能图标」页签照旧列着。
- 三类的方框尺寸统一为 80×80、图标 32px（16 网格的 2 倍），一行 10 个；电梯模式的中英文语义都是 12px，靠颜色分主次；尺寸只在 `.final-layout` 的 `--final-box` / `--final-icon` 定义一次。

去重只在类内做、不跨类 —— 同一个图标用在两个页签里，两类各放一个，tooltip 里写「也在：xxx」。类内去重按图标身份（Figma 节点号；没有节点号的按来源 + 名字），不按名字 —— 库里 `elevator-door-filded` 有两个同名不同形的节点，两个都会出现。悬停方框看全名、来源和用在哪几行。

横向对比的平台：AMC（参考）、内部工具（KFPS / IoT）、my KONE（MyDeviceView / 云视界 / 大屏）、LiveView，最后一列是建议的标准版。

导航栏的搜索框三个页签通用：输入即筛选**当前页签**那张表，范围是该表显示出来的文字（名称、细分状态、各平台的取值文字、标准版图标名），模糊匹配、不区分大小写。下载列那两个按钮上的 `SVG` / `PNG`、以及只在 tooltip 里的 Figma 节点号不参与匹配。关键词在切换页签时保留，页签上的计数始终是该类的总条数、不跟着搜索变。

## 「标准版」这一列是怎么定的

页面上一共 59 个不同的标准版图标，分三种来源，tooltip 里会标明每一个的真实出处：

- **库内引用（70 行）** —— 直接取 Design Token China 图标库里的现成字形，首选这条路。
- **非库内（9 行）** —— 库里确实没有对应字形，分三类：
  - 设计在 IOT Delivery 文件里按库规范画的 5 个
  - 从 TDesign Icons 0.4.7（Tencent，MIT）取素材、按 KONE icon 规范改造的 2 个
  - 本项目新画的 2 个

非库内的这 9 个**都没过 icon 评审**，在页面上带黄点标记，不能当已入库图标使用。

标准版图标**悬停即放大**：旁边浮出一个 160×160 的方形预览，图标按 128px（16 单位画框的整数 8 倍，笔画不糊）渲染，用来看 20px 显示框里看不清的细节。三个页签都支持。

标准版列的表头可以筛选，「有争议」的格子左上角有黄点，鼠标悬停看理由，点一下可以手动标记/取消。两张表各有一套：

| | 筛选档位 | 争议标记 |
|---|---|---|
| 模式图标 | 全部 / 已填充 / 未填充 / 新增/待确认 | 自动判定（带理由）+ 手动覆盖，粒度到行 |
| 其他实时数据图标 | 全部 / 新增/待确认 | 纯手动（这批字段还没有裁决记录），粒度到「行 + 候选图标」，所以两个并存候选的那两行可以分别标 |

手动标记存在浏览器 localStorage 里（两张表各一个 key），只在本机可见、不进仓库；筛选菜单底部有「全部清除」。注释列同理。

## 校验脚本

`tools/` 下有几支脚本，用来卡住页面的不变量 —— 改完 `index.html` 应该跑一遍。

```sh
cd tools
npm i          # 只有跑脚本才需要装依赖，看页面不需要
npm run check  # = check-page.mjs && check-sizes.mjs，约 40s
```

- `check-page.mjs` —— 行数、图标渲染（每个标准版图标都得有 path、fill 全是 `currentColor`、viewBox 是 16 单位画框）、tooltip 来源构成、筛选 / 搜索 / 注释列的交互、争议标记的落盘与恢复。
- `check-sizes.mjs` —— 两张表的列宽自洽：定宽列合计 + 平台列 是否等于声明的表宽。
- `npm run build` —— 跑 `normalize-icon.mjs`，把 TDesign 素材按 16 网格重新描边、布尔合并成单条 path。产物在 `tools/out/`，需要手工贴进 `index.html`。
- `npm run sheet` —— 出一张放大联络表（`tools/out/contact-sheet.png`），用来目视复核改造和新画的图标。

## 目录

```
index.html              页面本体（数据 + 样式 + 逻辑 + 全部选型注释）
assets/
  amc/  kfps/           两个平台的徽标截图，用于图形比对
  kone-logo.svg
tools/
  check-page.mjs        页面行为与规范校验
  check-sizes.mjs       表格列宽自洽校验
  normalize-icon.mjs    外部素材 → 16 网格单条 path 的改造流水线
  icons.config.mjs      改造配方；被替换掉的旧配方归档在 TDESIGN_ARCHIVE
  geometry.mjs          描边 / 布尔运算的几何工具
  contact-sheet.mjs     放大联络表
  out/                  各次核对的产物与一次性校验脚本
```

`tools/out/` 里那些子目录是每次选型 / 替换时写的一次性核对脚本和它们的产物（渲染对照图、逐像素拟合读数、尺寸测量等）。`index.html` 的注释里引用了这些路径作为证据，所以一并留在仓库里。

## 一点约定

- 图标必须从 Figma 取真实 SVG path 内联使用，不画近似图形、不引用会过期的 Figma URL。
- 颜色统一用 `fill="currentColor"`，由 CSS 控制。
- 从 Figma 导出的节点经常带一个铺满画框的白底 `<rect>`，或者（整节点导出时）带画板外层的背景 path，必须剥掉再内联。
- 改动图标后要同步的地方不止一处：`STD_ICONS` 的条目、`STD_ICON_DISPUTES` 的争议文案、`check-page.mjs` 的名单与计数注释、`icons.config.mjs` 的配方归档。具体每一处的理由都写在对应位置的注释里。
